# ForgeFlow AI — Technical PRD & Architecture

## 1. Project Objective

Build **ForgeFlow AI**, an AI-powered industrial operations platform that demonstrates:

* Simulated Industrial IoT telemetry
* Real-time-style machine monitoring using API polling
* Interactive 2D factory digital twin
* AI-based anomaly and incident analysis
* LangGraph multi-agent orchestration
* Google Gemini integration
* n8n automation
* Automated maintenance work orders
* PDF operational reports
* MongoDB persistence

The project must be technically strong, visually polished, modular, and easy to understand and maintain.

There are **no physical IoT sensors**. The project must use a realistic backend telemetry simulator and clearly treat the data as simulated industrial telemetry.

## Important Architecture Constraint

**Do NOT use WebSockets or Socket.IO.**

Use lightweight API polling from the frontend every 3–5 seconds for changing telemetry/status data.

Do NOT introduce:

* Redis
* Kafka
* Kubernetes
* Microservices
* GraphQL
* WebSockets
* unnecessary infrastructure

Keep the architecture modular but beginner-maintainable.

# 7. Industrial IoT Simulator

Create a backend telemetry simulator.

Each machine continuously produces:

```text
temperature
vibration
pressure
rpm
powerConsumption
utilization
```

Example:

```json
{
  "machineId": "M-104",
  "temperature": 82.4,
  "vibration": 7.2,
  "pressure": 4.8,
  "rpm": 1840,
  "powerConsumption": 91,
  "utilization": 93
```

Telemetry should change gradually and realistically.

Do not generate completely random values every time.

Create machine operating ranges.

# 13. AI Architecture

Use LangGraph to orchestrate the AI analysis.

Architecture:

```text
Critical Incident
       |
       v
Incident Analysis Agent
       |
       +----> Root Cause Agent
       |
       +----> Risk Assessment Agent
       |
       +----> Maintenance Agent
       |
       v
Final Recommendation
```

## Incident Analysis Agent

Identify what happened.

## Root Cause Agent

Determine probable cause from telemetry and machine context.

## Risk Agent

Determine failure/operational risk.

## Maintenance Agent

Generate recommended maintenance action.

Use Gemini as the reasoning model.

AI responses must be returned in structured JSON so the frontend can reliably render them.

Example:

```json
{
  "summary": "...",
  "probableCause": "...",
  "riskScore": 78,
  "confidence": 91,
  "recommendedAction": "...",
  "priority": "CRITICAL"
}
```

Use Docker only for n8n infrastructure.

Create:

```text

├── compose.yaml
└── .env.example
```
